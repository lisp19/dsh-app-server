# DSH App Server v1.2.0

服务端安装支持 npm `latest`、`next` 两个上游渠道，默认 `latest`：

```bash
dsh-server install --channel next
```

命令行选项优先于本机 JSON 的 `upstreamChannel`；安装成功后保存选择，后续 `install` 沿用该渠道。安装记录包含渠道、准确版本及锁文件摘要。下载失败不会自动切换渠道，日常 `restart` 不下载或升级上游。

从 v1.1.0 升级时，更新本项目源码及依赖，重新打包插件后执行安装。切换渠道前备份本机配置、完整 DSH home 和工作区；两个渠道不保证版本先后关系，降级可能需要数据迁移。操作见 [服务管理](https://github.com/lisp19/dsh-app-server/blob/v1.2.0/docs/server-management.md)。现有 v1.1.0 客户端可继续使用，不要求为渠道选项升级客户端。

文档按安装、使用、开发和引用整理，保留第三方版权及许可证原文。上游仍独立下载，不修改源码、不打入桌面包。

本地验证覆盖 npm `latest` 的 DSH `0.1.5-rc.3` 和 npm `next` 的 `0.1.7-rc.2`：实际安装、原生接口、供应商测试凭据保存、刷新和服务重启后持久化。这些版本是验证记录，不是安装限制。测试使用模拟模型及凭据，不代表真实供应商 OAuth 验收。发布流水线继续对默认 `latest` 执行原生集成、多平台构建及安装器检查。
